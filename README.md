# 🌦️ Weather to DOCX

`weather-to-docx` формирует компактный прогноз Microsoft Word по городам и координатам. Версия **0.3.2** ориентирована на быстрое чтение оператором, а не на выгрузку всех полей поставщика.

## Результат

Для каждой точки создаётся один альбомный документ A4 на **две страницы**.

Первая страница:

- краткий блок «Главное»;
- прогноз по дням на срок до 7 суток;
- температура, осадки, ветер и порывы, давление;
- оценка согласованности выбранных моделей;
- одна компактная таблица ансамблевой неопределённости.

Вторая страница:

- прогноз по контрольным срокам через 6 часов в первые трое суток;
- далее — через 12 часов;
- не более 18 строк;
- только погода, температура, осадки, ветер, влажность и давление.

Единицы в документе:

```text
°C
мм
м/с
гПа
%
```

Технические обозначения поставщика, англоязычные единицы, пустые колонки, повторные таблицы по каждой модели, почва, радиация, испарение и служебные метаданные в обычный отчёт не включаются.

## Как используются модели

Детерминированные модели сравниваются внутри одной сводки. По каждой модели не создаётся отдельный многостраничный раздел.

Перед расчётом система оценивает полноту ключевых полей:

```text
температура
осадки
ветер
порывы
давление
облачность
влажность
```

Неполный ряд исключается из сводки и указывается в шапке документа. Если ни одна модель не содержит температуры, ветра и давления, генерация завершается понятной ошибкой вместо документа из прочерков.

Для ансамбля запрашиваются только температура, осадки, давление, ветер, порывы и код погоды. В стандартный документ включается одна выбранная ансамблевая система.

## Выходные файлы

```text
одна точка     → DOCX
несколько точек → отдельные DOCX и общий ZIP
```

Рядом сохраняется `manifest.json` с источниками, контрольными суммами, предупреждениями и ошибками.

## Быстрый запуск

Требуется Python 3.11 или новее.

```bash
git clone https://github.com/f2re/weather-to-docx.git
cd weather-to-docx

python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[dev]'

weather-to-docx init
```

Запустить API:

```bash
weather-to-docx-api
```

В другом терминале запустить обработчик очереди:

```bash
weather-to-docx worker --poll-interval 5
```

Интерфейс:

```text
http://127.0.0.1:8080/
```

## Работа в браузере

1. Добавить город, адрес, координаты или файл TXT/CSV/JSON.
2. Выбрать детерминированные модели и при необходимости один ансамбль.
3. Указать горизонт от 1 до 7 суток и пороги осадков.
4. Нажать «Сформировать прогноз».

Формат документа фиксирован: альбомный A4, оперативный профиль, две страницы. Это исключает случайное создание широких 40–50-страничных отчётов.

Часовой пояс определяется локально по координатам. Для каждой точки сохраняется источник timezone: введён оператором, определён по координатам, получен при геокодировании либо взят как резервный.

## Telegram

Боту можно отправить:

```text
Псков
```

```text
57.8193, 28.3325
```

или TXT, CSV, JSON и Telegram-геопозицию.

Команды:

```text
/forecast  — справка по формированию прогноза
/cancel    — отменить последнее активное задание
/sources   — используемые модели
/settings  — настройки и состояние worker
/help      — помощь
```

Telegram и веб-интерфейс используют одну SQLite-очередь. Перезапуск бота не удаляет уже поставленное задание.

## Надёжная очередь

Worker использует:

- ограниченную аренду задания;
- heartbeat;
- идентификатор worker;
- число попыток;
- прогресс по комбинациям `точка × источник`;
- автоматический возврат просроченного задания в очередь;
- защиту от записи результата старым worker.

Диагностика:

```bash
curl -sS http://127.0.0.1:8080/api/v1/diagnostics | python3 -m json.tool
```

Службы:

```bash
systemctl status weather-to-docx-api
systemctl status weather-to-docx-worker
systemctl status weather-to-docx-telegram
```

## Автономная установка Astra Linux

Офлайн-комплект собирается в среде, совместимой с целевой Astra Linux.

После распаковки:

```bash
sudo ./setup.sh
```

Подписанный комплект:

```bash
sudo ./setup.sh --keyring /root/weather-release-keyring.gpg
```

Настройки:

```text
/etc/weather-to-docx/weather-to-docx.env
```

Данные:

```text
/var/lib/weather-to-docx/
```

Подробно: [`docs/OFFLINE_INSTALL.md`](docs/OFFLINE_INSTALL.md).

## Проверки

```bash
ruff check .
pytest
python -m compileall -q src
node --check src/weather_to_docx/static/app.js
node --check src/weather_to_docx/static/reliability.js
node --check src/weather_to_docx/static/compact_report.js
```

CI выполняется на Python 3.11, 3.12 и 3.13. На Python 3.11 контрольный семисуточный DOCX конвертируется LibreOffice в PDF, после чего `pdfinfo` проверяет, что документ содержит ровно две страницы.

Регрессионные тесты также проверяют:

- отсутствие `mm`, `m/s` и `hPa` в документе;
- отсутствие технических полей и повторных разделов;
- ограничение количества строк;
- исключение неполной модели;
- отказ от формирования документа, если ключевых данных нет;
- русские единицы `мм`, `м/с`, `гПа`;
- одну сводную таблицу по дням и одну таблицу контрольных сроков.
