# 🌦️ Weather to DOCX

`weather-to-docx` сравнивает прогнозы нескольких моделей и формирует оперативный документ Microsoft Word по каждой точке.

Текущая версия: **0.5.0**.

## Что изменилось в 0.5.0

Документ больше не начинается с технической выгрузки значений. Первая страница отвечает на основные вопросы специалиста:

- какое явление существенно;
- когда оно начнётся и достигнет максимума;
- сколько моделей его подтверждают;
- какую вероятность показывает ансамбль;
- насколько уверенным считается сигнал.

События получают понятный статус:

```text
Устойчивый сигнал
Вероятный сигнал
Отдельный сценарий
```

Одиночная модель не выдаётся за согласованный прогноз.

## Режимы документа

### Краткий

Сводка рисков, прогноз по дням, контрольные сроки и компактная ансамблевая таблица. Подходит для быстрого просмотра и отправки в Telegram.

### Экспертный — по умолчанию

Краткая сводка и отдельная полноразмерная метеограмма каждой пригодной модели. Ансамбль получает самостоятельную страницу неопределённости.

### Полный

Экспертный режим плюс дополнительные модельные таблицы. Использует A3 и предназначен для разбора исходных расчётных рядов.

Интерфейс показывает ориентировочное число страниц до запуска задания.

## Первая страница

Блок **«Ключевые риски»** содержит не более трёх событий. Для каждого события указываются:

- явление;
- временное окно;
- время максимума;
- ожидаемое значение;
- поддержка моделей;
- ансамблевая вероятность, если доступна;
- уровень уверенности.

Суточная таблица показывает общую уверенность. При одной модели колонка уверенности скрывается, поскольку межмодельную согласованность оценить невозможно.

## Научная логика

Межмодельная согласованность рассчитывается отдельно по:

- температуре;
- количеству осадков;
- ветру и порывам;
- типу погодного явления.

Осадки суммируются только по неперекрывающимся интервалам накопления. Дублирующиеся или перекрывающиеся интервалы не складываются повторно.

Для ансамбля сохраняются:

- медиана;
- 25-й и 75-й процентили;
- 10-й и 90-й процентили;
- количество доступных членов;
- полнота ансамбля;
- сырые вероятности превышения порогов.

Неполнота ансамбля уменьшает доверие к вероятностному сигналу. Разные ансамблевые системы не смешиваются в искусственный супер-ансамбль.

## Профессиональная метеограмма

Каждая метеограмма использует одну временную шкалу и пять отдельных панелей:

1. низкая, средняя и высокая облачность;
2. температура и точка росы;
3. относительная влажность;
4. осадки и вероятности порогов;
5. ветер, порывы, направление ветра и давление.

Дополнительно показываются:

- ночь — серыми вертикальными полосами;
- направление ветра — стрелками;
- минимум и максимум температуры;
- максимум осадков;
- грозовые интервалы;
- порог порывов 14 м/с;
- русские даты, единицы и подписи.

На ансамблевой метеограмме:

- тёмная полоса — 25–75-й процентили;
- светлая полоса — 10–90-й процентили;
- центральная линия — медиана.

Метод сглаживания не выводится в рабочей части документа. Техническая методика находится в [`docs/METEOGRAMS.md`](docs/METEOGRAMS.md).

## Контроль качества документа

После генерации выполняются два уровня проверки.

Структурная проверка контролирует:

- наличие метеограмм в DOCX;
- число крупных изображений;
- русские дни недели;
- наличие блока рисков;
- структурное число страниц.

При наличии LibreOffice и Poppler документ дополнительно преобразуется в PDF. Проверка ищет:

- пустые страницы;
- содержимое у физического края листа;
- возможное обрезание графика.

В результатах задания отображаются:

```text
DOCX проверен
метеограмм: N
страниц: N
результат визуальной проверки
```

Крупнейшая метеограмма сохраняется как отдельная миниатюра для просмотра до открытия DOCX.

## Быстрый запуск для разработки

```bash
git clone https://github.com/f2re/weather-to-docx.git
cd weather-to-docx
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[dev]'
weather-to-docx init
```

API:

```bash
weather-to-docx-api
```

Worker во втором терминале:

```bash
weather-to-docx worker --poll-interval 5
```

Интерфейс:

```text
http://127.0.0.1:8080/
```

## Правильное обновление установленной системы

Рабочая служба запускается из:

```text
/opt/weather-to-docx/current/venv
```

Обычный `git pull` не обновляет установленный Python-пакет. Используйте:

```bash
cd /путь/к/weather-to-docx
git switch main
git pull --ff-only origin main
./scripts/update.sh
```

Проверка:

```bash
/opt/weather-to-docx/current/venv/bin/weather-to-docx --version
/opt/weather-to-docx/current/venv/bin/weather-to-docx-verify --deep
```

Ожидаемая версия:

```text
0.5.0
```

## Входные данные

Можно передать:

- город или адрес;
- координаты;
- TXT;
- CSV;
- JSON;
- Telegram-геопозицию.

Для каждой точки формируется отдельный DOCX. Для нескольких точек создаётся общий ZIP.

DaData используется при наличии token. Без него применяется OpenStreetMap Nominatim. Часовой пояс определяется локально по координатам.

## Telegram

```text
/forecast  — сформировать прогноз
/cancel    — отменить активное задание
/sources   — показать модели
/settings  — настройки и состояние worker
/help      — помощь
```

Telegram и браузер используют общую SQLite-очередь.

## Astra Linux без Интернета

Сборка автономного комплекта:

```bash
INCLUDE_GRIB=0 OUTPUT_DIR=dist/offline ./scripts/build-offline-bundle.sh
```

Установка после переноса:

```bash
sudo ./setup.sh
```

Подписанный комплект:

```bash
sudo ./setup.sh --keyring /root/weather-release-keyring.gpg
```
