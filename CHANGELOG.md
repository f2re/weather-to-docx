# История изменений

## 0.4.0 — 2026-08-04

### Метеограммы

- для каждой пригодной детерминированной модели добавлена отдельная страница с компактной таблицей и метеограммой на весь срок;
- добавлена отдельная ансамблевая метеограмма;
- отображаются температура, точка росы, влажность, облачность, осадки, ветер, порывы и давление;
- низкие, средние и высокие облака показаны полупрозрачными слоями;
- ночные сроки обозначаются мягким затемнением;
- ансамбль показывает медиану, `q10–q90`, внутренний диапазон `mean ± σ` и вероятности порогов осадков;
- осадки остаются несглаженными столбиками в исходных интервалах.

### Научная и техническая реализация

- реализован shape-preserving PCHIP по схеме Fritsch–Carlson на чистом NumPy;
- пропуски и большие временные разрывы не соединяются;
- SciPy не требуется;
- добавлены Matplotlib и NumPy в обычную и автономную установку;
- worker использует backend `Agg` и постоянный каталог кэша Matplotlib;
- добавлены альтернативные описания встроенных изображений.

### Интерфейс и тесты

- добавлен переключатель метеограмм;
- режим без графиков сохраняет двухстраничный документ версии 0.3.2;
- добавлены тесты PCHIP, отсутствия overshoot, разрывов, PNG и встраивания в DOCX;
- LibreOffice проверяет физическую пагинацию: две сводные страницы плюс одна страница на модель и ансамбль;
- добавлена документация `docs/METEOGRAMS.md` с анализом открытых проектов и лицензий.

## 0.3.2 — 2026-08-04

### Документ

- вместо отдельных разделов по каждой модели формируется одна сводная таблица;
- отчёт фиксирован в альбомном A4 и рассчитан на две страницы;
- первая страница содержит главное, прогноз по дням и одну ансамблевую таблицу;
- вторая страница содержит контрольные сроки через 6 часов в первые трое суток и через 12 часов далее;
- технические поля, пустые колонки, повторные метаданные и англоязычные единицы удалены;
- единицы в документе приведены к `°C`, `мм`, `м/с`, `гПа`;
- неполные модельные ряды автоматически исключаются из сводного расчёта;
- если ни одна модель не содержит температуры, ветра и давления, генерация завершается понятной ошибкой вместо таблицы из прочерков;
- добавлена оценка согласованности моделей по дням.

### Получение данных

- Open-Meteo по умолчанию запрашивает только параметры, используемые в операторском отчёте;
- почва, радиация, испарение, поверхностное давление и другие исследовательские поля не загружаются без явного пользовательского запроса;
- ансамблевый запрос сокращён до температуры, осадков, давления, ветра, порывов и кода погоды.

### Интерфейс и проверки

- форма формирования документа сокращена до горизонта, порогов осадков и заголовка;
- горизонт обычного документа ограничен семью сутками;
- можно выбрать только одну ансамблевую систему;
- добавлены тесты русских единиц, отсутствия технических дублей и исключения неполной модели;
- LibreOffice в CI конвертирует контрольный DOCX в PDF, а `pdfinfo` проверяет ровно две страницы.

## 0.3.1 — 2026-08-04

### Надёжность

- добавлены lease, heartbeat и идентификатор worker для каждого задания;
- просроченные задания автоматически возвращаются из `running` в очередь;
- старый worker не может перезаписать результат после потери аренды;
- отмена останавливает выполняющуюся асинхронную задачу;
- сохраняются число попыток, текущий прогресс и понятное состояние обработки;
- API показывает доступность worker и метрики очереди.

### Координаты и импорт

- IANA timezone определяется локально по координатам;
- сохраняется происхождение timezone;
- старые записи 0.3.0 без происхождения не считаются автоматически проверенными;
- TXT, CSV и JSON разбираются единым серверным парсером;
- перед импортом показываются точки, координаты, timezone и предупреждения;
- данные сохраняются только после подтверждения оператора.

### Telegram и интерфейс

- Telegram переведён на общую SQLite-очередь;
- добавлена команда `/cancel`;
- интерфейс показывает состояние worker, прогресс и конкретные ошибки задания;
- видны ограничения горизонта отдельных моделей;
- блокируется нечитаемая комбинация A4 с расширенным профилем;
- настройки сервера применяются без зависимости от порядка HTTP-запросов.

### Установка

- исправлен сценарий `setup.sh --keyring`;
- `timezonefinder` включён в wheelhouse и автономный комплект;
- README и регламент приёмки приведены к фактическому поведению 0.3.1.

## 0.3.0 — 2026-08-04

### Изменено

- детерминированные модели выводятся первыми, по две таблицы на модель;
- ансамблевые системы перенесены в одну отдельную сравнительную таблицу в конце DOCX;
- среднее используется для температуры и давления;
- медиана используется как основной центр осадков, ветра и других асимметричных величин;
- квантили q10/q50/q90 рассчитываются методом Hyndman–Fan type 8;
- направление ветра усредняется круговым методом;
- вероятности осадков рассчитываются как сырая доля `M/N` по нескольким порогам;
- неполный ансамбль, число членов и дискретность `100/N` показываются явно;
- интерфейс сокращён до трёх рабочих шагов.

### Добавлено

- научный модуль обработки ансамблей;
- отдельный генератор научной композиции DOCX;
- DaData suggest, reverse и clean;
- ввод городов, адресов, координат, TXT, CSV и JSON;
- Telegram-бот с меню команд;
- выдача DOCX для одной точки и ZIP для нескольких;
- ограничение Telegram по user ID;
- systemd-служба Telegram;
- `weather-to-docx-api` и `weather-to-docx-telegram`;
- единый сценарий `setup.sh`;
- интерактивный мастер DaData, Telegram и моделей;
- документация по ансамблям, Telegram и DaData;
- тесты научных статистик, состава DOCX, геокодирования и Telegram.
