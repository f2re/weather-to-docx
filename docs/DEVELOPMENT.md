# Разработка и проверка

Обязательные правила разработки находятся в:

- [`AGENTS.md`](../AGENTS.md) — краткий контракт для всех кодовых агентов;
- [`docs/DEVELOPMENT_CONTRACT.md`](DEVELOPMENT_CONTRACT.md) — полный нормативный контракт;
- [`.github/pull_request_template.md`](../.github/pull_request_template.md) — обязательный чек-лист PR.

Ни человек, ни агент не должны начинать изменение только по старому локальному состоянию или предыдущему сообщению. Сначала проверяются текущая `main`, её SHA и версия.

## Начало работы

```bash
git fetch origin main
git switch main
git pull --ff-only origin main
git rev-parse HEAD
python scripts/check-version.py
python scripts/check-development-contract.py
git switch -c agent/<задача>-<дата>
```

До изменения кода прочитайте верхний раздел `CHANGELOG.md`, затронутые тесты и документацию компонента.

## Среда

```bash
python3.11 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[dev]'
```

Для прямого NOAA GFS требуется ecCodes, который входит в основные зависимости проекта и системную офлайн-сборку.

## Проверки

Быстрые проверки:

```bash
make check
```

Полный контракт агента:

```bash
make agent-check
```

Эквивалентный набор:

```bash
python scripts/check-version.py
python scripts/check-development-contract.py
ruff check .
pytest
python -m compileall -q src
node --check src/weather_to_docx/static/app.js
node --check src/weather_to_docx/static/reliability.js
node --check src/weather_to_docx/static/compact_report.js
weather-to-docx-verify --deep
```

Интеграционные тесты используют локальные фикстуры. Сетевое обращение не должно быть условием обычного Pytest.

## Обязательные проверки по типу изменения

### Версия или выпуск

```bash
python scripts/check-version.py
```

Версия берётся из `pyproject.toml`, не уменьшается и не меняется в обычной feature/fix-ветке. Файловый маркер выпуска, Git-тег и GitHub Release проверяются отдельно.

### DOCX и метеограммы

Требуются:

- регрессионный тест структуры;
- проверка изображений и подписей;
- `weather-to-docx-verify --deep`;
- физический рендер LibreOffice/Poppler в CI;
- сохранение контрольного артефакта.

### Зависимости и runtime

Требуются сборка wheel, проверка точки входа и автономного комплекта. Обновление не должно уничтожать базу и настройки.

### Источники и научные расчёты

Требуются официальная компактная фикстура, тест отсутствующих данных, единицы, интервальная семантика и честные метаданные цикла/срока.

## Добавление параметра

1. Добавьте описание в доменный каталог параметров или профиль извлечения.
2. Нормализуйте поле в адаптере.
3. Укажите единицу, исходное имя и качество.
4. Для расчётного поля установите `QualityFlag.CALCULATED`.
5. Добавьте поле только в соответствующий режим документа.
6. Проверьте корректное, отсутствующее и подозрительное значение.
7. Не возвращайте техническую колонку в основной операторский отчёт без отдельного требования.

## Добавление источника

1. Создайте адаптер в `sources/`.
2. Реализуйте `ForecastSource.fetch`.
3. Заполните `SourceDescriptor` и `SourceMetadata`.
4. Используйте текущий `weather_to_docx.__version__`, а не строковый номер.
5. Зарегистрируйте источник в `SourceRegistry`.
6. Сохраните компактную официальную фикстуру.
7. Добавьте автономный тест без сетевого обращения.
8. Обновите `docs/SOURCES.md` и эксплуатационные ограничения.

## PR и слияние

PR создаётся как draft. В описании фиксируются базовый SHA, версия, тесты и ограничения. Ready for review и слияние разрешены только после полного успешного CI.

После слияния обязательно повторно проверить:

```bash
git fetch origin main
git show --no-patch --format=%H origin/main
git show origin/main:VERSION
```

Нельзя сообщать о слиянии, версии, теге или релизе по памяти.

## Коммиты

Коммиты должны быть небольшими и описывать законченный результат:

```text
Добавлена проверка согласованности версии
Исправлена семантика интервальных осадков
Добавлен контракт визуальной приёмки DOCX
```

Секреты, реальные `.env`, закрытые ключи, большие GRIB и сгенерированные производственные документы в репозиторий не добавляются.
