# 🛰️ Источники прогнозов

Документ фиксирует, что именно получает система, откуда берутся данные и какие ограничения нельзя скрывать от оператора.

## 1. Реализованные источники

| Идентификатор | Поставщик и модель | Транспорт | Горизонт | Точный цикл | Назначение |
|---|---|---|---:|---|---|
| `open_meteo_gfs` | Open-Meteo / NOAA GFS | JSON HTTPS | до 16 суток | нет в стандартном ответе | быстрый рабочий и резервный канал |
| `noaa_gfs_0p25` | NOAA/NCEP GFS 0.25° | отфильтрованный GRIB2 | до 384 ч | да | воспроизводимый официальный источник |
| `demo` | встроенный генератор | локально | до 168 ч в CLI | синтетический | проверка установки, не прогноз |

## 2. Open-Meteo GFS

### Endpoint

```text
https://api.open-meteo.com/v1/gfs
```

### Запрашиваемые группы

- температура, точка росы, влажность, ощущаемая температура;
- давление на уровне моря и у поверхности;
- ветер на 10 м и порывы;
- осадки, дождь, ливни, снег и вероятность осадков;
- общая и ярусная облачность, видимость;
- CAPE;
- коротковолновая, прямая и рассеянная радиация;
- продолжительность солнечного сияния;
- эвапотранспирация, ET₀ и дефицит давления водяного пара;
- температура и влажность почвы по слоям.

### Достоинства

- простой почасовой JSON;
- не требуется локальный декодер GRIB;
- подходит для быстрого развёртывания;
- удобен как независимая проверка прямого декодирования.

### Ограничения

- это агрегирующий канал, а не непосредственная выдача NOAA;
- стандартный ответ не содержит точное время исходного цикла GFS;
- пространственная и временная обработка выполняется сервисом;
- доступность и лимиты внешнего API находятся вне контроля установки.

В документе канал подписывается как `NOAA GFS через Open-Meteo`, а не просто `GFS`.

## 3. NOAA GFS 0.25° через NOMADS

### Endpoint фильтра

```text
https://nomads.ncep.noaa.gov/cgi-bin/filter_gfs_0p25.pl
```

### Файлы продукта

```text
gfs.YYYYMMDD/CC/atmos/gfs.tCCz.pgrb2.0p25.fFFF
```

где:

- `CC` — цикл `00`, `06`, `12` или `18 UTC`;
- `FFF` — заблаговременность в часах;
- `pgrb2.0p25` — регулярная сетка 0.25°.

Адаптер получает только заданные уровни, параметры и прямоугольник вокруг точки. Полный глобальный файл не загружается.

### Запрашиваемые GRIB-поля

```text
TMP RH DPT PRMSL PRES UGRD VGRD GUST
APCP ACPCP TCDC LCDC MCDC HCDC
VIS CAPE CIN DSWRF PWAT HPBL WEASD SNOD
```

### Внутренние расчёты

- скорость и направление ветра рассчитываются из `UGRD/VGRD` и маркируются `calculated`;
- интервальные осадки рассчитываются из накопленного `APCP` и маркируются `calculated`;
- погодный код выводится по локальным правилам приоритетов;
- срок и цикл берутся из GRIB и сохраняются в метаданных.

### Зависимости

`eccodes` входит в основную зависимость приложения, поэтому обычная установка
`python -m pip install weather-to-docx` уже включает декодер GRIB2. Для
системного Python без wheel-пакетов установите библиотеку ОС:

```bash
sudo apt install libeccodes0 libeccodes-data
```

В закрытой установке эти пакеты должны присутствовать в офлайн-комплекте.

## 4. Параметры адаптеров в YAML

### Open-Meteo

```yaml
- source_id: open_meteo_gfs
  forecast_days: 10
  options:
    cell_selection: nearest
```

Для испытательного внутреннего зеркала можно переопределить endpoint:

```yaml
options:
  endpoint: https://weather-gateway.example.test/v1/gfs
```

### Прямой GFS

```yaml
- source_id: noaa_gfs_0p25
  forecast_days: 7
  options:
    hourly_to_120: true
    max_concurrency: 4
    box_degrees: 0.5
    # Фиксированный цикл для воспроизводимой генерации:
    # cycle: 2026-08-03T12:00:00Z
```

`hourly_to_120: true` означает шаг 1 час до +120 ч и 3 часа далее. При `false` используется шаг 3 часа по всему горизонту.

## 5. Планируемые источники

### NOAA GEFS

Назначение: вероятность превышения порога осадков, ансамблевое среднее, квартили и разброс. GEFS не будет выводиться как обычный детерминированный почасовой ряд на максимальном горизонте.

### ECMWF IFS Open Data

Назначение: независимый глобальный детерминированный прогноз. Будет реализован прямой GRIB2-адаптер с обязательной атрибуцией и сохранением цикла.

### ECMWF AIFS

Назначение: отдельная секция машинно-обученной модели. AIFS не будет смешиваться с IFS под одним названием.

### DWD ICON Global

Назначение: независимая глобальная модель. Требует отдельной обработки нативной треугольной сетки либо регулярных интерполированных продуктов.

### ECCC GDPS

Назначение: дополнительная независимая детерминированная модель с обязательной атрибуцией ECCC.

## 6. Запрещённые упрощения

- нельзя выдавать детерминированные осадки за вероятность;
- нельзя считать точный цикл известным, если API его не сообщил;
- нельзя заменять пропущенный параметр нулём;
- нельзя смешивать сроки из разных циклов одной модели;
- нельзя подписывать агрегатор именем исходной модели без указания канала;
- нельзя незаметно использовать предыдущий цикл после отказа нового;
- нельзя линейно интерполировать тип осадков, грозу или максимальный порыв.
