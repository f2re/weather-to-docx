# 📈 Профессиональные метеограммы

## Назначение

Версия 0.4.0 сохраняет короткую двухстраничную сводку и добавляет наглядные приложения:

```text
страница 1 — прогноз по дням и главное
страница 2 — контрольные сроки
страница 3 — таблица и метеограмма модели 1
страница 4 — таблица и метеограмма модели 2
...
последняя страница — ансамблевая таблица и метеограмма
```

Неполные модельные ряды не получают отдельную страницу.

## Детерминированная метеограмма

Метеограмма строится на весь доступный срок модели и состоит из четырёх синхронных панелей:

1. Полупрозрачная облачность: низкая, средняя и высокая; при отсутствии слоёв — общая.
2. Температура, точка росы и относительная влажность.
3. Осадки за нативный интервал источника.
4. Ветер, порывы и давление на уровне моря.

Ночные сроки обозначаются лёгким затемнением фона. Все панели используют одну локальную временную шкалу точки.

## Сглаживание

Температура, влажность, облачность, давление и ветер сглаживаются монотонным кубическим методом PCHIP по схеме Fritsch–Carlson.

Преимущества:

- линия проходит через исходные сроки;
- не создаются новые экстремумы;
- монотонный участок остаётся монотонным;
- пропуски и большие временные разрывы не соединяются;
- SciPy не требуется.

Осадки не сглаживаются. Они выводятся столбиками в исходных временных интервалах, поскольку сглаженная кривая осадков создавала бы физически ложные значения между сроками.

## Ансамблевая метеограмма

Для ансамбля отображаются:

- медиана или доступный центральный прогноз;
- внешний диапазон `q10–q90`;
- внутренний диапазон температуры `mean ± σ`, ограниченный внешним диапазоном;
- диапазоны ветра, влажности, облачности и давления;
- `q90` порывов;
- медианные осадки;
- сырые вероятности превышения выбранных порогов осадков.

Разные ансамблевые системы не смешиваются. В стандартном документе используется одна выбранная система.

## Источники визуальных решений

Перед реализацией изучены открытые проекты:

### `milankl/prob_meteogram`

Проект показывает неопределённость через полупрозрачность, отделяет облачные слои от осадков и строит вероятностные поля. Лицензия MIT допускает использование подходов, однако код в проект не копировался.

### `metno/yrmeteo`

Реализация MET Norway использует единую временную шкалу, суточные разделители, температурные диапазоны, осадки и ветер. Проект распространяется по LGPL-3. В `weather-to-docx` применены только общие принципы композиции.

### `marhoy/meteogram`

Современный пакет демонстрирует компактный пользовательский формат метеограммы на данных met.no. Лицензия GPL-3 несовместима с прямым заимствованием без изменения лицензирования всего продукта, поэтому код не использовался.

### `wdtinc/meteogram-py`

Проект предлагает объектную модель `Meteogram` и `SubPlot`, но является старым Python 2 alpha-пакетом и не содержит ясно обнаруживаемой лицензии. Он не включён в зависимости.

## Архитектура

```text
src/weather_to_docx/plotting/smoothing.py
    PCHIP и разбиение ряда по пропускам

src/weather_to_docx/plotting/meteogram.py
    PNG детерминированной и ансамблевой метеограмм

src/weather_to_docx/document/meteogram_document.py
    страницы моделей и встраивание изображений в DOCX
```

Рендер выполняется Matplotlib с backend `Agg`. Изображения создаются во временном каталоге, встраиваются в DOCX, после чего временные файлы удаляются.

## Параметры API

```json
{
  "include_meteograms": true,
  "meteogram_smoothing": "pchip",
  "meteogram_dpi": 180
}
```

Допустимые режимы сглаживания:

```text
pchip   — рекомендуемый shape-preserving режим
linear  — линейные отрезки без кубической интерполяции
```

Разрешение: от 96 до 360 dpi.

```text
matplotlib

fonttools

cycler

```

SciPy не требуется. Для одинакового вида на Astra Linux устанавливается `fonts-liberation2`; резервный шрифт — DejaVu Sans.

## Проверки

Автоматические тесты проверяют:

- отсутствие overshoot на монотонном PCHIP-ряду;
- отсутствие соединения через пропуски;
- создание непустого PNG;
- детерминированный и ансамблевый режимы;
- встраивание изображений с описанием доступности;
- одну страницу на каждую модель;
- сохранение двухстраничного режима при отключённых метеограммах;
- реальную пагинацию LibreOffice → PDF.
