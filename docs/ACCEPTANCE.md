# ✅ Приёмка Weather to DOCX 0.3.2

Версия считается принятой, когда для каждой точки формируется понятный альбомный DOCX A4 на две страницы, а перезапуск API, worker или Telegram не приводит к потере задания.

## 1. Автоматические проверки

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[dev]'

ruff check .
pytest
python -m compileall -q src
node --check src/weather_to_docx/static/app.js
node --check src/weather_to_docx/static/reliability.js
node --check src/weather_to_docx/static/compact_report.js
weather-to-docx sample --output var/acceptance --hours 24
```

Обязательные проверки документа:

- один сводный прогноз вместо повторных разделов по моделям;
- не более семи строк в суточной таблице;
- не более 18 строк контрольных сроков;
- ровно один явный разрыв страницы;
- при наличии LibreOffice — ровно две страницы после конвертации в PDF;
- отсутствие `mm`, `m/s`, `hPa`;
- наличие `мм`, `м/с`, `гПа`;
- отсутствие MSL, SFC, CAPE, CIN, VPD, ET₀, почвы и радиации в обычном отчёте;
- исключение неполной модели;
- отказ с понятной ошибкой, если ключевых данных недостаточно.

## 2. Структура DOCX

### Первая страница

Должны присутствовать:

- название точки и период;
- координаты и местный часовой пояс;
- перечень моделей, вошедших в сводку;
- короткий блок «Главное»;
- таблица «Прогноз по дням»;
- температура, осадки, ветер, порывы, давление;
- оценка согласованности моделей;
- компактная ансамблевая таблица, если ансамбль выбран.

### Вторая страница

Должна присутствовать одна таблица:

```text
Дата и время
Погода
Температура
Осадки
Ветер
Влажность
Давление
```

Сроки выбираются:

- через 6 часов в первые трое суток;
- через 12 часов далее;
- не более 18 строк на весь документ.

## 3. Недопустимое содержимое

В обычном документе не допускаются:

- отдельные многостраничные таблицы по каждой модели;
- почасовые 7-суточные листинги;
- повторная служебная шапка перед каждой моделью;
- идентификаторы `open_meteo_*`;
- англоязычные названия продуктов и единицы;
- атрибуция и лицензия после каждой таблицы;
- колонки, состоящие преимущественно из прочерков;
- MSL и SFC одновременно;
- радиация, почва, испарение и технические диагностические поля;
- вероятность осадков без порога или периода.

## 4. Полнота моделей

Проверить набор с тремя полноценными моделями и одной неполной моделью, содержащей только порывы и давление.

Ожидаемый результат:

- полноценные модели участвуют в сводке;
- неполная модель не создаёт отдельную таблицу;
- в шапке есть короткое объяснение её исключения;
- прочерки неполной модели не попадают в рабочие таблицы.

Отдельно проверить набор, в котором ни одна модель не содержит температуры, скорости ветра и давления. Задание должно завершиться понятной ошибкой, а не DOCX из пустых ячеек.

## 5. Единицы и формат чисел

Проверить весь извлечённый текст DOCX.

Допустимо:

```text
18,4 °C
2,6 мм
5,1 м/с
1016 гПа
70 %
```

Не допускается:

```text
18.4 C
2.6 mm
5.1 m/s
1016 hPa
```

В пользовательском документе используется десятичная запятая.

## 6. Получение данных

По умолчанию детерминированные Open-Meteo-источники должны запрашивать только поля оперативного отчёта:

```text
температура и ощущаемая температура
влажность и точка росы
осадки и снег
код погоды
давление на уровне моря
облачность
ветер, направление и порывы
видимость
CAPE для определения погодного явления
признак дня и ночи
```

Для ансамбля:

```text
температура
осадки
давление
скорость ветра
порывы
код погоды
```

Явный `options.hourly` должен сохранять возможность специального исследовательского запроса, но такие поля не должны автоматически появляться в компактном DOCX.

## 7. Веб-интерфейс

Проверить:

1. Горизонт ограничен диапазоном 1–7 суток.
2. Формат A4 и оперативный профиль не требуют выбора оператором.
3. Интерфейс объясняет структуру двух страниц.
4. Можно выбрать несколько детерминированных моделей.
5. Одновременно используется не более одного ансамбля.
6. Старая кнопка не создаёт второе параллельное задание.
7. При недоступном worker кнопка формирования заблокирована.
8. После создания отображаются прогресс и конкретные ошибки.

## 8. Очередь

1. Создать задание с двумя точками и двумя источниками.
2. Убедиться, что `progress_total` равен четырём.
3. Запустить worker и проверить изменение `progress_current`.
4. Аварийно остановить worker во время выполнения.
5. Дождаться истечения lease.
6. Запустить новый worker.
7. Убедиться, что задание вернулось в очередь и получило новую попытку.
8. Проверить, что старый worker не может перезаписать новый результат.
9. Отменить выполняющееся задание.

Диагностика:

```bash
curl -sS http://127.0.0.1:8080/api/v1/diagnostics | python3 -m json.tool
```

## 9. Часовые пояса

Проверить:

| Точка | Ожидаемый timezone |
|---|---|
| Хельсинки | `Europe/Helsinki` |
| Санкт-Петербург | `Europe/Moscow` |
| Владивосток | `Asia/Vladivostok` |

Местное время во всех таблицах должно соответствовать timezone точки.

## 10. Импорт

Загрузить файл с корректными координатами, городом, повтором и ошибочной строкой.

До сохранения система должна показать:

- распознанные точки;
- координаты;
- timezone;
- предупреждения;
- повторы;
- пропущенные строки.

Ни одна точка не записывается до подтверждения.

## 11. Telegram

1. Отправить город, координаты и файл.
2. Убедиться, что задания появляются в общей очереди.
3. Перезапустить Telegram-службу во время выполнения.
4. Проверить `/cancel`.
5. Проверить выдачу DOCX для одной точки и ZIP для нескольких.
6. Проверить, что Telegram получает тот же компактный документ, что браузер.

## 12. Реальная пагинация

В CI на Python 3.11:

1. создаётся семисуточный документ с несколькими моделями и ансамблем;
2. LibreOffice Writer конвертирует DOCX в PDF;
3. `pdfinfo` проверяет:

```text
Pages: 2
```

Дополнительно документ необходимо открыть в Microsoft Word и LibreOffice на целевой Astra Linux и проверить отсутствие восстановления файла, обрезанных колонок и переноса третьей таблицы на дополнительную страницу.

## 13. Автономная установка Astra Linux

```bash
sudo bash scripts/build-astra-apt-repository.sh dist/apt-repository
bash scripts/build-offline-bundle.sh
```

На машине без сети:

```bash
sha256sum -c weather-to-docx-offline-*.tar.zst.sha256
tar --zstd -xf weather-to-docx-offline-*.tar.zst
cd weather-to-docx-offline-*
sudo ./setup.sh --keyring /root/weather-release-keyring.gpg
```

Проверить сохранность базы, настроек, работу API/worker/Telegram, `doctor --deep`, обновление и откат.

## 14. Критерий выпуска

Выпуск разрешён, когда:

- CI зелёный на Python 3.11, 3.12 и 3.13;
- LibreOffice подтверждает две страницы;
- все единицы русские;
- неполные ряды исключаются;
- пустые технические поля отсутствуют;
- сквозной тест очереди проходит после перезапусков;
- офлайн-комплект собирается и проверяется;
- контрольный документ принят в Word и LibreOffice.
