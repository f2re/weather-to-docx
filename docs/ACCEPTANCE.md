# ✅ Приёмка Weather to DOCX 0.5.1

Версия считается принятой, когда документ позволяет специалисту за 15 секунд определить главное явление, время начала и максимума, интенсивность, поддержку моделей, ансамблевую вероятность и уровень уверенности.

## 1. Автоматические проверки

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[dev]'

python scripts/check-version.py
ruff check .
pytest
python -m compileall -q src
node --check src/weather_to_docx/static/app.js
node --check src/weather_to_docx/static/reliability.js
node --check src/weather_to_docx/static/compact_report.js
weather-to-docx-verify --deep
```

CI выполняется на Python 3.11, 3.12 и 3.13. Python 3.11 дополнительно использует LibreOffice и Poppler. Проверка версии должна подтвердить одинаковое значение в `pyproject.toml`, `VERSION`, пакете, метаданных адаптеров, конфигурациях и документах текущего выпуска.

## 2. Первая страница

Обязательные элементы:

- название точки, период, координаты и местное время;
- перечень пригодных моделей и исключённых неполных рядов;
- блок «Ключевые риски»;
- прогноз по дням;
- общая уверенность при наличии не менее двух моделей;
- краткое объяснение средней или низкой уверенности.

Для каждого риска должны быть указаны:

```text
явление
временное окно
время максимума
ожидаемое значение
поддержка N из M моделей
ансамблевая вероятность, если доступна
устойчивый / вероятный / отдельный сценарий
уровень уверенности
```

При одной модели не допускаются колонки или формулировки «Согласованность» и «одна модель».

## 3. Межмодельный сигнал

Проверить следующие сценарии:

1. Грозу показывает одна из трёх моделей — статус «Отдельный сценарий».
2. Грозу показывает большинство моделей — «Устойчивый сигнал».
3. Событие поддерживает часть моделей и умеренная ансамблевая вероятность — «Вероятный сигнал».
4. Неполный ансамбль не повышает уверенность: вероятность учитывает покрытие членов.
5. Одиночный малозначимый сценарий не попадает в три главных риска.

## 4. Согласованность

Оценка должна учитывать отдельно:

- разброс максимальной температуры;
- факт и количество осадков;
- ветер и порывы;
- тип погодного явления.

При расхождении моделей документ должен кратко указать причину, например:

```text
06.08: температура — высокая, осадки — низкая, ветер — средняя, явление — низкая.
```

## 5. Осадки

Обязательна проверка семантики накопления:

- одинаковые интервалы не суммируются дважды;
- перекрывающиеся интервалы не складываются как независимые;
- при отсутствии start/end step используется одно значение на срок валидности;
- в вероятностной подписи присутствуют порог и период накопления.

## 6. Режимы документа

### Краткий

- сводка рисков;
- прогноз по дням;
- контрольные сроки;
- компактная ансамблевая таблица;
- без полноразмерных метеограмм.

### Экспертный

- краткая сводка;
- отдельная свободная страница метеограммы каждой модели;
- отдельная ансамблевая метеограмма;
- без повторной суточной таблицы над графиком.

### Полный

- экспертный режим;
- дополнительные модельные и ансамблевые таблицы на самостоятельных страницах;
- формат A3.

## 7. Динамическая компоновка

- 1–3 суток: сводка и контрольные сроки не разделяются принудительно;
- 4–7 суток: контрольные сроки переходят на следующую страницу;
- метеограмма не должна размещаться под таблицей;
- не допускаются пустые страницы;
- в экспертном режиме каждая модель добавляет одну страницу, ансамбль — одну страницу.

## 8. Метеограмма

Проверить при масштабе 100 %:

- заголовок полностью виден;
- временная шкала полностью видна;
- легенды не перекрываются;
- подписи имеют читаемый размер;
- русские дни недели;
- ночные интервалы заметны;
- низкая, средняя и высокая облачность представлены отдельными полосами;
- влажность вынесена в отдельную панель;
- присутствуют стрелки направления ветра;
- отмечены минимум и максимум температуры;
- отмечен максимум осадков;
- грозовой интервал визуально выделен;
- показан порог порывов 14 м/с.

## 9. Ансамблевая метеограмма

Обязательны:

- медиана;
- внутренний диапазон 25–75 процентов;
- внешний диапазон 10–90 процентов;
- вероятности превышения заданных порогов осадков;
- количество и полнота членов в документе или метаданных;
- отсутствие искусственного объединения разных ансамблей.

## 10. Свежесть данных

На странице модели должны быть видны:

```text
цикл модели или честная отметка, что цикл поставщик не передал
время получения
предупреждение, если данные старше 12 часов
```

Время формирования документа не должно выдаваться за время цикла модели.

## 11. Физическая проверка

При наличии LibreOffice и Poppler:

1. DOCX преобразуется в PDF.
2. `pdfinfo` определяет фактическое число страниц.
3. Страницы преобразуются в PNG.
4. Проверка выявляет:
   - пустые страницы;
   - содержимое у физического края листа;
   - потенциальное обрезание изображения.

В metadata DOCX-артефакта должны присутствовать:

```text
meteograms
rendered_pages
visual_check
blank_pages
edge_touch_pages
risk_section
russian_weekdays
```

Геометрическая автоматическая проверка не заменяет финальную ручную приёмку в Microsoft Word и LibreOffice на целевой Astra Linux.

## 12. Веб-интерфейс

Проверить:

1. Доступны режимы «Краткий / Экспертный / Полный».
2. Экспертный режим выбран по умолчанию.
3. До запуска показывается ориентировочное число страниц и состав разделов.
4. Одновременно выбирается не более одного ансамбля.
5. Техническая диагностика свёрнута.
6. После выполнения показываются:
   - миниатюра метеограммы;
   - число метеограмм;
   - число страниц;
   - результат структурной или визуальной проверки;
   - состояние русских подписей.
7. В кратком режиме маленькие погодные пиктограммы не выдаются за миниатюру метеограммы.

## 13. Очередь и восстановление

Проверить lease, heartbeat, повтор после аварии worker, защиту от записи старого worker, отмену активного задания и сохранение результатов после перезапуска API/Telegram.

## 14. Автономная установка Astra Linux

```bash
sudo bash scripts/build-astra-apt-repository.sh dist/apt-repository
bash scripts/build-offline-bundle.sh
```

На машине без сети:

```bash
sha256sum -c weather-to-docx-offline-*.tar.zst.sha256
tar --zstd -xf weather-to-docx-offline-*.tar.zst
cd weather-to-docx-offline-*
sudo ./setup.sh --keyring /root/weather-release-keyring.gpg
```

Проверить wheel с новыми модулями, LibreOffice/Poppler при необходимости, сохранность базы, обновление и откат.
