# ✅ Приёмка Weather to DOCX 0.3.1

Версия считается принятой, когда оператор может добавить одну или несколько точек, проверить часовые пояса, выбрать модели, создать устойчивое задание и получить отдельный DOCX для каждой точки и общий ZIP. Перезапуск API, worker или Telegram не должен приводить к потере задания.

## 1. Автоматические проверки

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[dev]'

ruff check .
pytest
python -m compileall -q src
node --check src/weather_to_docx/static/app.js
node --check src/weather_to_docx/static/reliability.js
weather-to-docx sample --output var/acceptance --hours 24
```

Обязательные группы тестов:

- нормализация метеорологических параметров;
- научные ансамблевые статистики;
- порядок секций DOCX;
- постоянный справочник координат;
- очередь SQLite;
- миграция базы версии 0.3.0;
- аренда и heartbeat задания;
- восстановление просроченного `running`;
- блокировка записи старого worker;
- локальное определение IANA timezone;
- серверный предпросмотр TXT/CSV/JSON;
- Telegram-меню и общая очередь;
- автономный установочный комплект.

## 2. Приёмка очереди

1. Создать задание с двумя точками и двумя источниками.
2. Убедиться, что `progress_total` равен четырём.
3. Запустить worker и проверить изменение `progress_current`.
4. Аварийно остановить worker во время выполнения.
5. Дождаться истечения lease.
6. Запустить новый worker.
7. Убедиться, что задание вернулось в очередь и получило новую попытку.
8. Проверить, что старый worker не может перезаписать новый результат.
9. Отменить выполняющееся задание и убедиться, что вычислительная задача прекращена.

Диагностика:

```bash
curl -sS http://127.0.0.1:8080/api/v1/diagnostics | python -m json.tool
```

Должны присутствовать:

```text
worker.online
worker.last_seen_utc
queue.queued
queue.running
queue.stale_running
```

## 3. Приёмка часовых поясов

Проверить минимум следующие точки:

| Точка | Ожидаемый timezone |
|---|---|
| Хельсинки | `Europe/Helsinki` |
| Санкт-Петербург | `Europe/Moscow` |
| Владивосток | `Asia/Vladivostok` |

Сценарии:

1. добавить координаты без timezone;
2. убедиться, что timezone определён локально;
3. добавить точку с явно заданным timezone;
4. убедиться, что он помечен как `explicit`;
5. открыть каталог версии 0.3.0 без `timezone_source`;
6. убедиться, что запись не считается автоматически подтверждённой;
7. создать новое задание и проверить корректное местное время в DOCX.

## 4. Приёмка импорта

Загрузить файл, содержащий:

- корректные координаты;
- город;
- повтор координат;
- ошибочную строку;
- точку без timezone.

До сохранения система должна показать:

- число найденных точек;
- названия;
- координаты;
- timezone каждой точки;
- предупреждение для повтора и ошибочной строки.

Ни одна точка не должна записываться в каталог до нажатия кнопки подтверждения.

## 5. Приёмка веб-интерфейса

1. Остановить worker.
2. Открыть интерфейс.
3. Убедиться, что система явно показывает недоступность worker.
4. Убедиться, что кнопка создания задания недоступна.
5. Запустить worker и дождаться автоматического обновления статуса.
6. Выбрать горизонт больше горизонта ICON и проверить видимое предупреждение.
7. Выбрать A4 и расширенный профиль: отправка должна быть заблокирована с понятным объяснением.
8. Создать задание и наблюдать прогресс `выполнено/всего`.
9. При частичном результате открыть перечень конкретных ошибок.
10. Скачать DOCX, ZIP и `manifest.json`.

## 6. Приёмка Telegram

1. Отправить город.
2. Отправить координаты.
3. Отправить TXT или CSV с несколькими точками.
4. Убедиться, что все задания появились в общей SQLite-очереди.
5. Перезапустить Telegram-службу во время выполнения: задание должно сохраниться.
6. Выполнить `/cancel` и проверить отмену последнего активного задания.
7. Остановить worker: бот должен сообщить о проблеме до постановки нового задания.
8. Проверить предупреждения входного файла в сообщении бота.

## 7. Приёмка DOCX

Каждый документ проверить в Microsoft Word и LibreOffice:

- открывается без восстановления;
- содержит правильное название и координаты;
- местное время соответствует timezone точки;
- детерминированные модели идут первыми;
- каждая модель содержит наглядную и подробную таблицы;
- ансамбли находятся в одном завершающем разделе;
- отсутствующие значения обозначены как `—`;
- рассчитанные и сомнительные значения имеют признаки качества;
- заголовки таблиц повторяются на новых страницах;
- строки не разрываются между страницами;
- нет макросов и внешних изображений.

Расширенный и полный профиль принимаются в формате A3. A4 на этом этапе предназначен для оперативного профиля.

## 8. Приёмка автономной установки Astra Linux

Комплект собирается в совместимой Astra Linux:

```bash
sudo bash scripts/build-astra-apt-repository.sh dist/apt-repository
bash scripts/build-offline-bundle.sh
```

На машине без сети:

```bash
sha256sum -c weather-to-docx-offline-*.tar.zst.sha256
tar --zstd -xf weather-to-docx-offline-*.tar.zst
cd weather-to-docx-offline-*
sudo ./setup.sh --keyring /root/weather-release-keyring.gpg
```

Проверить:

- подпись реально проверяется указанным keyring;
- `pip` не обращается в Интернет;
- системные пакеты берутся только из вложенного APT;
- API и worker запускаются;
- `doctor --deep` формирует DOCX;
- timezonefinder присутствует в wheelhouse;
- обновление сохраняет базу и настройки;
- откат возвращает предыдущий релиз;
- Telegram-служба включается только при наличии token.

## 9. Критерий выпуска

Выпуск разрешён, когда:

- CI зелёный на Python 3.11, 3.12 и 3.13;
- сквозной тест оператора проходит после перезапусков;
- очередь восстанавливает просроченное задание;
- timezone проверен минимум на трёх географических регионах;
- предпросмотр импорта не записывает данные до подтверждения;
- Telegram использует общую очередь;
- DOCX открывается в Word и LibreOffice;
- офлайн-комплект устанавливается на целевом стенде Astra Linux.
